OQ-6 appropriately keeps measured latency and budget calibration open. The remaining recovery ambiguity is a specific decision to settle, recorded under Done-ness clarity.

The vision identifies the actual disagreement: “which uncertainty, which experiments count, what was advanced” (§1). No extra personas or market-positioning section is needed for this small writing team.

## Strategic coherence — strong

The feature sequence follows one clear thesis: decide framing in small units, reconcile the complete plan, then draft prose. FR-8 ties later ideas to earlier decisions, FR-15 makes approval reconciliation of the whole selected plan, and FR-23 freezes that plan before drafting. §8’s exclusions keep this an experience improvement to the existing generation pipeline, rather than an unrelated platform expansion.

The metrics now match that thesis reasonably well. SM-4 measures corrections-to-acceptable; SM-C4 checks unsupported claims without treating honest `[GAP]` markers as failures; SM-C2 includes cancelled generations when checking request volume. SM-5 now measures Feedback requests with “at least one of their Revised Seeds selected,” closing the penalty against useful alternatives. SM-2 explicitly calls itself an “event-gap proxy for effort” and requires validation against five observed sessions before its threshold binds. That is an honest operational approximation for these stakes, not a claim to measure attention directly.

All 41 FRs have testable consequences. The most serious pass-2 problems are closed: FR-15 checks carried selections as well as the current Batch; FR-40 preserves the immutable consumed revision; FR-17 derives Stale from approved versus current revisions; FR-14/FR-25 carry Skip through drafting; and FR-19 distinguishes writer concurrency from asynchronous attempt ownership. ### Findings

- **medium** Missing advancement references can survive non-linear navigation (§4.2 FR-8, `prd.md:223`; §4.3 FR-15/FR-16, `prd.md:296`, `prd.md:308`; §4.5 FR-20) — Structured references are required “whenever Subsection 9 has active Seed Selections,” but opening Subsection 11 before any experiment is selected remains legal. Such a Seed can have no experiment references; after experiments are selected, the Batch becomes Outdated, and the writer can use Confirm and approve. The rejection rule only names an item “any of whose references is no longer active,” which does not explicitly reject missing references. FR-16’s general promise that an item names its supporting experiments does not explain how that earlier item acquires valid links, and Seed Edit only edits bullets. *Fix:* Define the approval/sign-off predicate as requiring exactly one active uncertainty reference and at least one active experiment reference for every selected advancement, regardless of when it was generated. Specify whether writers can edit links or must regenerate, and cover the zero-experiments-at-generation path in the semantic fixtures. Also state how selecting alternatives for the same uncertainty preserves “one advancement per resolved uncertainty.”
- **medium** Editing a Feedback target does not change the result’s freshness identity (§2 Context Revision; §4.3 FR-11/FR-12, `prd.md:257`, `prd.md:264`; §4.4 FR-40) — Recording “its wording at request time” fixes historical lineage, but the Subsection’s Context Revision includes Predecessors and its own active Feedback, not the target Seed’s current wording. If Larry requests a revision of “cloud experiment,” edits that Seed to “on-premise experiment” while the request runs, and adds no new Feedback, the old cloud revision can arrive without an Outdated marker. This also happens when the target is unselected, so Selection Revision does not necessarily help. *Fix:* Compare the recorded target wording/revision with the current target on completion and selection/approval, then visibly identify a superseded-target result and require explicit reconciliation, or include the target revision in a dedicated Feedback freshness check. Preserve the immutable request record.
- **medium** Budget extension does not specify how an exhausted initial allowance recovers (§4.6 FR-27, `prd.md:440`; §5 NFR-3, `prd.md:539`; §4.2 FR-5/FR-6) — The finite allowance and dispatch reservation close the unlimited-call defect, but after three failed initial attempts FR-27 offers “the budget extension, if available, or cancel.” The extension increases the global cap by 20; it does not explicitly grant another initial attempt or allow a first successful Batch to use ordinary remaining capacity. For example, three failures can leave a role failed after only six requests, while extending 60 to 80 changes none of its eligibility rules. FR-6 also still says a diversity failure “is regenerated once,” whereas FR-5 says structured-output repair is the “only automatic retry.” *Fix:* State how an exhausted role can consume extension capacity, or remove extension as a recovery option if it cannot. Define when initial allowance applies and explicitly make diversity retry share the same two-request attempt envelope. Keep the total bound and truthful cancel outcome.
- **medium** Batch latency includes time the writer chooses not to view a result (§5 NFR-1, `prd.md:537`; §4.8 FR-33, `prd.md:495`; §4.2 FR-5) — NFR-1 measures from request to the Batch “being shown,” while FR-33 defines shown as “when a user first renders it.” With prefetch and non-linear navigation, a Batch can complete in five seconds and remain unviewed for an hour, failing the 30-second p95 through no latency defect. Multiple users also produce several view events for one Batch. *Fix:* Measure request-to-ready/completion for background work and, if needed, a separate request-to-render metric for a foreground request that remains open. Specify the event and sample population for each percentile. Retain first-view events for exposure counts.

## Shape fit — adequate

A capability-oriented PRD with four load-bearing journeys fits this internal tool and its meaningful UX change. Its length is defensible because it feeds UX, architecture and epics and must distinguish human approval, model requests and immutable generation history. Most mechanisms remain in the addendum; the binding revision and lifecycle rules belong in the PRD because they determine what the writer sees and approves.

The brownfield commitments align with the supplied context: existing mode identity, one active generation, unchanged generation-status vocabulary, three report headings, project prose-edit capability and the existing report creation path. PRD §0 acknowledges the implemented edit and guidance controls shown in `extract-codebase.md` §§3 and 5. Calling the problem “a discoverability and unit-of-review problem” remains a product interpretation rather than a verified usability diagnosis, but OQ-7 keeps discovery open and the new flow follows the supplied handoff. Extra personas, market analysis or compliance-process sections would not improve this document’s usefulness.
