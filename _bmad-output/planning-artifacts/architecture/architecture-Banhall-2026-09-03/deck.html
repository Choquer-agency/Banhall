Paradigm and layers

Event-sourced workflow core + pipes-and-filters AI engine + governed-knowledge sidecar, all on Convex.

  • Workflow core. projects is the aggregate root; every human state change appends to projectEvents / workItemEvents; denormalized pointers and counters move in the same transaction.
  • AI engine. Fixed pipelines (analyzer, section agents, scrub, compress, QA) composed as scheduled Convex actions with durable run rows and CAS claims. No generic agent framework, no supervisor swarm.
  • Knowledge sidecar. Brain (RAG over admin-approved sources) and learning digests (admin-published candidates). Both feed prompts; neither writes prose or workflow state.

Dependency direction

Arrows point at what a layer may import. shared/ imports nothing app-specific; the client reaches Convex functions only through convex/_generated/api. Documented only today; a vitest import-direction check is the target enforcement (AD-1).

Deployment topology

Operational envelope, as found

  • Frontend on Vercel via the git integration; no CD workflow in the repo. Backend on Convex; prod deployed from a developer machine, no staging (AD-22 target).
  • Auth: Better Auth, email and password, invite-only in two layers, no email verification, no MFA (Q14).
  • Model egress: Anthropic direct, OpenRouter for openai/* and google/*, Voyage for embeddings and rerank, optional MS Graph OneDrive.
  • Crons: stale generations (30 min), stale PD reviews, post-QA and chat turns (15 min); oversight and my-work sweeps every 5 min; nightly digests 08:00 / 08:15 UTC.
  • CI runs npm run check and npm test only: no convex tsc, no build, no component tests, no deploy.
  • Inbound: no rate limits; /ingestion/upload is one shared bearer key, 15 MB cap, extension allowlist. Observability is errorReports and aiUsage; nobody is paged (Q13).

Agents propose, humans apply

AI output that touches prose lands only as a chatProposals row in state pending. A human moves it to applied through one of the AD-3 revision writers.

Proposal lifecycle

Every transition out of pending is a writer action. Reference-only proposals insert as applied because they carry no prose.

Generation lifecycle

Frozen inputs, stamped provenance, one active generation per project (AD-5). Single, compare, and iterative modes share the reserve, claim, complete, reap shape.

Brain governance

Sources are candidates until an admin acts; the vector index holds only approved rows and every retrieval re-joins on status. Revoke is confirmed erasure (AD-6). Dotted edges are stubs.

Learning loop

Solid edges are live. The loop closes into prompts and provenance, then stops: nothing reads the provenance back.

What is agreed but not built

Target rules: agreed in the spine, not yet enforced in code.

  1. AD-11Trusted-context boundary: all client text enters as delimited, labelled, budgeted data blocks; system prompt is policy plus style only.
  2. AD-11aInterim before the next document-bearing feature: fence the transcript, remove the instruction grant from writer's notes, move chat grounding out of system, add an injection test.
  3. AD-12Learning must be measurable: every signal has a reader and a health metric at /admin; digests need writer and project diversity.
  4. AD-13De-identify before firm-wide knowledge: importSource strips client identities; raw signal rows store de-identified text.
  5. AD-19Project-scoped rows follow the project: a listed cascade with blobs, agent threads, and Brain tombstones; today 8 of 49 tables.
  6. AD-20Every egress of client text is registered and class-gated: a processing register, OpenRouter data_collection deny, research consent flag.
  7. AD-21Data classes C1 to C4 and their handling: no client text in logs or errorReports; read audit on non-owned projects.
  8. AD-22Environments and deploy path: dev, staging, prod; convex deploy from CI with a held key; codegen diff and build in CI.

Is it a step up over pasting into ChatGPT?

Yes, today

  • Workflow. Stages, ownership, work items, and handoffs are event-sourced with optimistic concurrency and a dashboard projection that moves in the same transaction (AD-2, AD-14).
  • Provenance. Every generation freezes its inputs byte-for-byte and stamps prompt version and digest ids; export re-authorizes on revision and hash (AD-5, AD-8).
  • Human-gated proposals. No tool can touch prose; a proposal is a pending row until a writer applies it through a fenced, snapshotting writer (AD-3, AD-4).
  • Governed knowledge. Brain sources and digests are candidates until an admin acts; revoke is confirmed erasure; rollback is a ledger entry (AD-6).
  • Cost metering. One routing point, one action budget, every call in aiUsage with generation and run attribution (AD-9).

Not yet

  • The learning loop is not measurable. Provenance is written and never read; post-edit distance is never stored; no evals (AD-12, divergence #12).
  • The trust boundary is open. Chat grounding lives in the system prompt, the transcript is unfenced, trust derives from a client-settable category (AD-11, #9).
  • Data lifecycle and erasure. Delete cascades 8 of 49 project tables and no blobs; no egress register, no data classes, no retention windows (AD-19, AD-20, AD-21, #43, #44).
  • Authorization ceiling. Roughly 50 write paths, including deletes, egress, and spend, authorize on the firm-wide read gate (AD-7, #39).

Security review verdict: a good workflow spine and a weak confidentiality spine. Ship-blocking for a client-facing confidentiality claim; the interim AD-11a mitigations are the cheap fix for writers today.
