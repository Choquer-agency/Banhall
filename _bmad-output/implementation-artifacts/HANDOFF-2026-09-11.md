### Recovery recipe (learned the hard way — follow exactly)

Every interruption so far was operational, not a code defect. When a story escalates, stalls, or the engine dies:

1. **Preserve first.** In the unit worktree (`.bmad-loop/runs/<run>/worktrees/<n>`): `git add -A`, `git diff --cached --binary > <scratch>/story-N.patch`, `git commit-tree` the index onto HEAD, `git branch preserve/story-N-<run> <sha>`, `git reset -q`. Never lose a session's uncommitted work.
2. **Gate it** if you intend to carry it (`bash scripts/loop-verify.sh` in that worktree; use its own `node_modules`).
3. **Carry it onto the target** (`plan/pd-generation` in the main checkout): `git apply --index` the patch. In the story file, **delete the `baseline_revision:` line** and set `status:` to `in-review` if it passed the gate and was complete, or `in-progress` if unfinished. Commit.
   - Why: the engine compares the spec's `baseline_revision` with the baseline it records at re-arm; a stale value fails with "spec baseline … does not match orchestrator-recorded baseline" and burns an attempt (this cost story 1 a full attempt). `--restore-patch` is unsupported under worktree isolation.
4. **Make sure the main checkout is clean** (`git status --short` empty). Uncommitted tracked changes there block the engine's merge ("merge … blocked: the target checkout has uncommitted changes"). That is how the `.factory` deletions were found.
5. **Restart.** Prefer a **fresh run** (`bmad-loop run --spec …` in the tmux engine window): it skips stories whose committed spec says `done`, and gives the in-flight story two fresh attempts. `bmad-loop stop` + `resume` on the same run consumes an attempt. For a pure escalation where you want the same run: `bmad-loop resolve <run> --no-interactive --no-resume`, then `bmad-loop resume <run>`.
6. If a story's work is already committed on the run branch but the merge was blocked, fast-forward it by hand (`git merge --ff-only bmad-loop/<run>` on the target) instead of re-arming.

Other hazards seen:
- **Account session limits** stall Opus/Sonnet sessions (`env_fault: true`); wait for the reset, preserve, carry, restart.
- **Memory**: the Mac has 16 GB and swaps heavily with Arc, several Claude sessions, ChatGPT/Codex, Slack etc. open. Each story runs typecheck, svelte-check, ~2,200 unit tests and a production build. Ask Johnny to close apps rather than killing anything yourself.
