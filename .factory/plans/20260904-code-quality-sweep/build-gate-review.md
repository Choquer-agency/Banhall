# Production build in the default DX gate

Recommendation: **add `npm run build` to the default `scripts/loop-verify.sh` gate in pending DX-1**, preserving browser-free execution and the optional final `VERIFY_COMPONENT=1` step. This fits the existing script/docs/CI scope and six acceptance criteria. No build, deployment, or product edit was performed for this review.

The added check covers an observed gap. The recorded deterministic baseline passes check and 1,413 unit tests, while slop-1's one-placeholder build failed because installed `@mmailaender/convex-better-auth-svelte` imports both public URL constants from `$env/static/public` (`dist/sveltekit/index.js:3`). The dependency's server adapter is consumed by `hooks.server.ts`, the root server layout, and the auth API route. With both placeholders the baseline build passed, exit 0 in **44.393 seconds wall time** (`build-baseline.log:302`); slop-1's subsequent build also passed (`.audit/slop-1-dead-components/build-after.log`, Vite reports 26.51s). Keep Vite's own timing distinct from end-to-end wall time. This additional cost is reasonable against the existing **55.841-second** gate and configured **20-minute** timeout. A combined duration must still be recorded after implementation.

Build safety is appropriate for the default gate. `package.json` maps build only to `vite build`, with no prebuild/postbuild deploy command. The configured Vercel adapter writes local `.vercel/output` and `.svelte-kit` artifacts (`node_modules/@sveltejs/adapter-vercel/index.js:48-77`); it does not publish them. Current routes contain no prerender declaration, auth API proxy `fetch` is inside the request handler, and the root auth hook/load use cookie/token state. The recorded placeholder build already succeeds without a live Convex backend. This is build verification, not proof of an authenticated user flow.
