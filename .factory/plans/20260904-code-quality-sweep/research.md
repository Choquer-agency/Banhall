# Research: code quality, performance and agent verification sweep

Plan dir: `.factory/plans/20260904-code-quality-sweep`. Baseline: `sprint2-boundary` at `11bfe3e`, clean. Inputs: `idea.md`, the three auditor reports in this dir (`slop-audit.md`, `performance-audit.md`, `dx-audit.md`), `performance-benchmark.mjs`, `component-baseline.log`, `uploader-baseline.log`. Every auditor claim used below was re-checked with `rg` or by reading the cited lines; where a claim was not re-checked it is marked so.

## Intent

For the maintainer and every agent that opens this repo: remove code and tests that nothing runs, make the two test runners the only test runners, fix two measured hot-path wastes, and make verification one command that says what failed and why. "Done" is falsifiable: every `*.test.ts` in git is discovered by `vitest.config.ts` or `vitest.component.config.ts` (a script proves it and runs in the gate); `bun:test` appears nowhere; the nine abandoned component files, the eight My Work files and the test-only helper exports are gone with `rg` proving no reference remains; `parseFileToText` on a multi-page PDF leaves zero pending timers and a twenty-pair proposal preview walks the document once, both pinned by unit tests that fail at baseline; `npm run test:component` exits 0; CI runs exactly `bash scripts/loop-verify.sh` plus the browser suite; `README.md` describes this SvelteKit app. Findings not fixed are listed in `## Inventory` with a reason and a next proof.

Assumptions (no human answer needed to proceed):
- Seven of the eight component-test failures at baseline (`component-baseline.log:384-535`) are stale fixtures or class-token contracts after the 2026-08 rail and button changes; the eighth (`WorkspaceHeader.component.test.ts:164`) also exposes a likely mobile touch-target regression that must be measured, not re-pinned (`dx-audit.md:51-66` has the per-row mechanism, commit and correction). The ticket that fixes them follows that table; a regression is fixed in the component, never in the assertion.
- `tests/` stays the home for cross-runtime pure suites (they import from `convex/`, `src/` and `shared/` at once). Moving them beside their modules would be cosmetic churn; wiring the directory into vitest is a one-line include change [1 laziness protocol].
- No production or shared Convex deployment is touched. Every metric in this plan comes from `node`, vitest or Chromium on the local checkout.

Performance
- PERF-1 `withDeadline` (`src/lib/parseDocument.ts:64-73`) never clears its timer; the PDF path calls it once for load and twice per page (`:187,190,191`), so a successful N-page parse leaves 2N+1 pending timers for up to 60 s. Baseline measured by the auditor with the real helper: 201 operations, 201 timers pending after completion (`performance-audit.md:12`). Repeatable in vitest with `vi.useFakeTimers()` and `vi.getTimerCount()`, controlling only the `pdfjs-dist` boundary via `vi.mock`. Existing tests: `src/lib/parseDocument.test.ts` (no PDF-path case).
- PERF-2 `buildDecorationSet` (`Editor.svelte:496-509`) calls `findAllOccurrencesCI` per proposal pair, which calls `buildSearchIndex(doc)` (`:261`, a full `doc.descendants` walk, `:137`) every time; `findReplaceMatches` (`:1110-1127`) repeats it. Baseline from `performance-benchmark.mjs` on real `@tiptap/pm` documents: 20 pairs, 30 builds, 600 traversals, median 63 ms (22.8k chars) and 282 ms (91.5k chars). The helpers live in a `<script module>` block, so root vitest cannot import them; they must move to a `.ts` module to be unit-testable in the gate. `src/lib/components/editor/` has no unit test today.
- PERF-3 `uploadDocument` collects every project document before deciding dedupe is ineligible for empty content (`convex/documents.ts:83-92`). Source-proven; no repeatable read-count metric exists without extracting the handler. Deferred (inventory).
- Bundle: `src/routes/project/[id]/+page.svelte:7-8` statically imports both `CurrentProjectPage.svelte` (1853 lines) and `PreviewProjectPage.svelte` (2331 lines); only one renders. No fresh build baseline exists (auditor's manifest is dated 2026-08-24). Deferred: needs `npm run build` before and after, and lazy-loading the rollback surface is a product decision (`?workspace=current` must still restore instantly).
