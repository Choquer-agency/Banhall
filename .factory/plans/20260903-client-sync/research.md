## Intent

Three independent follow-ups from the 2026-08-26 client sync, for the Banhall consulting team (Michael, the writers Larry/Tracy et al.) and for the developer who inherits them.

**A. Multiple transcripts per project.** Today a project holds exactly one transcript row and generation reads exactly one, sliced at 500 000 characters. Tracy needs to attach several transcripts, and a single two-hour transcript already strains the model's context window. Done means: a project can hold N ordered, labelled transcripts; generation consumes all of them; when the combined text exceeds a configured budget an explicit condensation step produces a stored, provenance-linked digest that preserves SR&ED-relevant facts; reports and generations reference the *set* of transcripts (and digests) used, with `sourceTranscriptId` still populated for old readers.

**B. New workspace dashboard on for everyone.** The preview workspace is gated behind a master appSettings switch plus a per-user allowlist, so writers are on the old UI and Michael cannot reproduce their bugs (transcript 13:00, 17:21). Done means: every authenticated user holding `project.readInternal` gets the workspace, with role-based permissions inside it unchanged, `?workspace=current` still working as rollback, and the now-inert admin rollout controls retired or clearly marked so nobody believes they still gate anything.

**C. Client uploader finds zero documents on OneDrive.** On Michael's Windows machine every input mode prints `Found 0 document(s)` in ~10 s, for a huge `Applications` tree and for small fully-synced folders alike (transcript 02:57–09:45). Done means: the reproduction is captured in a unit-testable filter function, the filter keeps OneDrive cloud placeholders while still skipping real links, a zero-result run prints and logs an actionable skip breakdown, and a `pwsh` test harness wired into the gate proves it.

### Falsifiable "done"

- A: `npx tsc -p convex/tsconfig.json --noEmit` and `npm test` green with new Convex tests covering N-transcript storage/ordering, generation input assembly below and above budget, digest persistence, the provenance list, and legacy single-transcript back-compat.
- B: the gate tests that currently assert the rollout gate are rewritten to assert "any `project.readInternal` holder gets `available: true`", and `rg` finds no live caller of the master switch as a gating input.
- C: `pwsh -File scripts/client-uploader/tests/*` exits 0 against a temp tree, including a case that fails on today's filter (a file carrying the ReparsePoint attribute with no link target) and passes after the fix.

### Assumptions

Stated here rather than blocking (principle 21, never block on the human):

1. The condensation budget is a configured constant in the repo, not a per-project user setting. No UI for tuning it in this plan.
2. Condensation uses the existing `convex/ai/` model/gateway plumbing and an existing configured model; no new provider, no new key.
3. "Retire the admin rollout controls" means remove or visibly mark inert in the UI and neuter the gating read; the `workspaceDashboardAccess` and audit tables stay (the idea says no destructive migration), so this plan widens/ignores, never narrows.
4. C's reproduction cannot be run on this Mac against a real OneDrive Files-On-Demand root. The proof is a unit test against a faked `FileInfo`-shaped object with the ReparsePoint attribute set, per the idea's own instruction to factor the filter into a testable function.
5. `[orchestrator].max_parallel = 1` in `.factory/roles.toml`, so the "run in parallel" wish in the idea is expressed as dependency ordering and disjoint `touches`, not as concurrency this run will actually use.

6. Condensation runs on the default Anthropic model (`shared/generationModels.ts:1`, `MODEL = "claude-sonnet-5"`) through `instrumentedAnthropic`, once per transcript per content hash, shared by every candidate. Budget constants are repo constants inside the prompt program (so `promptVersion` changes when they change): combined transcript budget 200 000 chars, condense window 160 000 chars, digest target 24 000 chars per transcript. These are starting values, not measured; the ticket names them as constants to tune.
7. A project may hold zero transcripts. Empty-content rows (still inserted by `convex/ingestionPort.ts:206-212`, which is out of scope) are legacy placeholders and are dropped by the one read helper.
8. "Retire the admin rollout controls" is implemented as deletion of the card, its mount and the admin functions; the tables stay. Marking them inert would leave 300 lines of dead UI to explain.

### C — Client uploader

**Codebase map.** `scripts/client-uploader/` holds `banhall-uploader.ps1` (356 lines), `banhall-uploader.sh` (339), `Run-Uploader.bat` (8), `Run-Uploader.command` (4), `setup.sh` (81), `README.txt` (38), `DEV-HANDOFF.md` (49), plus gitignored `uploader-config.json` and `upload-log.txt`. No subdirectories, no `tests/`.

The ps1 is a linear top-level script with only four helpers: `Save-Root` (`banhall-uploader.ps1:60-63`), `Pick-Folder` (`:66-79`), `Get-DropPrefix` (`:185-199`), `Write-Log` (`:259-261`). Collection, filtering, prompting and upload all run at top level.

**The bug.** The whole filter is inline in one `Where-Object` block, `banhall-uploader.ps1:209-215`:

```
209	    $files = Get-ChildItem -Path $r -Recurse -File -ErrorAction SilentlyContinue |
210	        Where-Object {
211	            -not ($_.Attributes -band [IO.FileAttributes]::ReparsePoint) -and
212	            -not $_.Name.StartsWith("~$") -and
213	            -not $_.Name.StartsWith(".") -and
214	            $allowedExt -contains $_.Extension.ToLower()
215	        }
```

`:211` drops every file carrying the `ReparsePoint` attribute. OneDrive Files-On-Demand sets that attribute on every file under the sync root, including files pinned "Always keep on this device", which is exactly Michael's symptom and exactly why the Mac passes (`banhall-uploader.sh:197` uses `find -type f` with default no-follow and has no attribute concept at all). `$_.LinkType`, the property that would distinguish a real symlink or junction from a cloud placeholder, is **not used anywhere in the file**. The preamble comment at `:201-204` shows the intent was to skip links.

Two structural consequences for the fix:
1. The filter is not a function, so it cannot be unit-tested today. Extracting it into a function taking a `FileInfo`-shaped object is a precondition for the idea's own proof strategy, not an optional tidy-up (principle 9, build the lever).
2. `-ErrorAction SilentlyContinue` at `:209` makes access-denied directories vanish uncounted, and the `Where-Object` discards silently. **No skip reason is counted anywhere.** That is why the run reports a bare zero.
