# Stress test (F5)

Plan: `docs/todos/phase-f-scale.md`, F5. A local deployment only, with real models and a spend cap the owner sets.

1. `node scripts/stress/generate.mjs --out /tmp/stress --names names.json`: 50 files of 400,000 characters, one at the 1,000,000-character maximum, one a character over it, and a 3-hour interview, all in invented words. It stops if any name from the list appears in the text, or if an invented name shares a word of 4 or more letters with one. `names.json` is a JSON array of the deployment's names (clients and their other names, projects, interviewees, speakers, users).
2. `node scripts/stress/run.mjs --data /tmp/stress --checkout <checkout running convex dev> --subject <auth subject of an internal user> --cap <USD> --confirm-spend --out /tmp/stress-results.json`. It refuses a checkout without a local deployment and reads only through it (`--deployment local`). Before writing anything it reads the deployment's names itself and checks every file against them and against the manifest's fingerprints. It makes the company, then a project named as a release eval project with no transcript, marks it as an evaluation project (left out of learning, writer memory, edit size and the Brain) and stops if that fails, and only then adds the interview. It uploads every file (the one over the maximum must be refused, naming the limit), waits for search pieces and file labels, and starts a Step by step draft to its Seeds. Each step records its time, result, its own spend, and characters per token by feature and model; the deployment's function log is kept beside the results (`<out>.log`).
3. The spend is read inside every wait; the run stops 10 percent (at least $1) below the cap and cancels a running draft, and cancels one left running if the script ends any other way. File labels already queued keep running in the background, so leave room under the cap.
4. The later steps (20 picks in one step, a 46-entry Brief, every check failing, chat at scale, a duplicate, two drafts at once, 100 files) are run by hand and added to the results.
5. Erase the project, then the company, through the app afterwards. The project's creator is the user given by `--subject`; use a test user made for the run.
