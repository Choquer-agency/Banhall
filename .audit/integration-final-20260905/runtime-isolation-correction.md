# BMAD runtime isolation correction

A fresh published-status repair stopped at the exact bmad-build entry command because `_bmad/scripts/render_skill.py` was missing. `_bmad/` is intentionally gitignored and is absent from fresh manual Git worktrees. This was an installation/runtime prerequisite, not a product-policy ambiguity. Root verified the missing files and seeded26unchanged installed runtime/config files from the completion checkout into each of the published-status and feedback-read repair checkouts, excluding existing render outputs, backups and Python bytecode. All seeded hashes match and both Git statuses remained clean. Re-entering the exact skill command in the owning worktree is the supported entrypoint; no workflow-source bypass or native-state edit was used.

The repair coordinator reported that earlier DW96–99 bmad-build startup calls used the original Banhall installation as renderer project-root, which generated ignored workflow snapshots there, while implementation/spec/audit edits and commits stayed in private worktrees. Therefore earlier blanket statements that the original checkout was wholly untouched were too broad: its tracked product source and ledger were not modified by those repairs, but ignored runtime snapshots were written. This is retained as a correction, not hidden or retroactively relabelled as perfectly isolated startup. Root instructed the coordinator to stop that route. No historic original snapshots were deleted because other ongoing work may reference them.

All current/future repair startup now uses its own seeded runtime and its own project-root/skill-root. Native-loop workers already had their own runtime; the completed native learning run is not being altered or restarted. Existing repair commit identities, baseline regressions, canonical tests and fresh source reviews remain independently verified on their actual private source revisions. Final main promotion still requires integrating and reviewing both current repairs, rerunning combined checks and recording deferred recommendations only after proof.
