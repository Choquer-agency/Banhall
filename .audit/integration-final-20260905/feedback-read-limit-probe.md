# Feedback transaction read-limit probe

Confirmed at exact combined revision `8c8080576d30c919f825e12f4b786f3f28b86b8f` in `/Users/johnnynguyen/Documents/Repos/Banhall-bmad-feedback-probe`. This is bounded BMAD code-review candidate verification, not a source repair or final gate.

The final real convex-test fixture registers the installed agent component and enables default transaction limits. It persists 49 prior turns with 180,000-character user prompts and short assistant answers, then a small latest completed turn. All writes use reportChatAgent.saveMessages; largest returned stored message is 360,266 bytes including duplicated search text, well below 1MiB with substantial metadata headroom. Prompts are below the explicit 1,000,000-character bound in `convex/chatV2.ts:533`. The fixture does not depend on a model producing unusually large answers.

Actual authenticated `api.chatV2.listMessages` at the panel's initial page size80 succeeds and returns80 rows containing the latest completed answer (`src/lib/components/chat/AgentChatPanel.svelte:227`). Actual authenticated `api.chatFeedback.submitFeedback` then fails with `Read too much data in a single function execution (limit: 16777216 bytes)`. No feedback row persists. Deleting only prior component messages makes the identical submitFeedback mutation succeed, storing the latest answer ID/text and vote. These are assertions in `convex/feedbackReadLimit.probe.test.ts`, not mocked query responses. Probe exits0 because it asserts this known-bad production outcome and the causal deletion control; it does not establish that production feedback passes with history.

Cause: `convex/chatFeedback.ts:44` requests100 full successful messages at/before target order, including earlier turns, before its in-memory exact-order answer filter. Installed agent `src/component/messages.ts:639-680` bounds upper order only, merges streams and paginates requested count. `publicMessage` line46 retains message and extracted text (omits parentMessageId, stepId, files). `convex-test/dist/transactionMetrics.js:11` defaults bytesRead16MiB; lines86-91 enforce it. Thus a count bound is insufficient even when the actual80-message UI request fits.

Own npmci, no private environment or production edits. `source-evidence.json` captures exact source/probe hashes and empty tracked diff. Initial exploration used long answers and a smaller component page; final retained probe strengthened this to valid large user prompts and the actual authenticated UI query at80, superseding those exploratory assumptions.
